# Product

## Register

product

## Users

พนักงานหน้าร้านและหลังร้านของร้านขายโทรศัพท์มือถือ แบ่งเป็น 4 บทบาท: ผู้ดูแลระบบ,
ผู้จัดการ, พนักงานขาย, ช่างเทคนิค

บริบทการใช้งาน: ยืนอยู่หน้าเคาน์เตอร์ ในร้านที่มีแสงไฟสว่าง มีลูกค้ารออยู่ตรงหน้า
งานที่ต้องทำเสร็จเร็วที่สุดคือ "ปิดบิลให้ลูกค้า" และ "รู้ว่าเครื่องรุ่นนี้เหลือกี่เครื่อง"
ใช้ทั้งจอเดสก์ท็อปหลังเคาน์เตอร์และแท็บเล็ต/มือถือเวลาเดินนับสต๊อก

ทุกข้อความใน UI เป็นภาษาไทย ฟอนต์ Anuphan (รองรับไทย + latin)

## Product Purpose

Mobistock คือระบบจัดการคลังสินค้าและขายหน้าร้าน (POS) สำหรับร้านมือถือที่ขายสินค้า
แบบ serialized — แต่ละเครื่องมี Serial/IMEI เกรด และสถานะของตัวเอง ไม่ใช่แค่จำนวนนับ

ระบบครอบคลุม: รับสินค้าเข้าคลัง, จัดการรุ่นสินค้าและสต๊อกรายเครื่อง, ขายหน้าร้าน,
ดูประวัติการขาย และ (ยังไม่พัฒนา) เคลม ซ่อม 3PL จัดการผู้ใช้

สำเร็จเมื่อ: พนักงานปิดบิลได้โดยไม่ต้องคิด และผู้จัดการเห็นของที่ใกล้หมดก่อนที่มันจะหมด

## Brand Personality

สะอาด ไว้ใจได้ ไม่ต้องคิด

เสียงของระบบเป็นเสียงเพื่อนร่วมงานที่พูดตรง ไม่ใช่ซอฟต์แวร์ที่พูดศัพท์เทคนิค
ข้อความ error บอกว่าเกิดอะไรขึ้นและทำอะไรต่อได้ ไม่ใช่รหัสข้อผิดพลาด
สีหลักเป็นฟ้า (brand hue ~250) ที่สืบทอดมาจากดีไซน์เดิม แต่เข้มพอให้อ่านออก

## Anti-references

- **แดชบอร์ด SaaS ที่มีการ์ดตัวเลขใหญ่ 6 ใบเรียงกัน** — ตัวเลขควรอยู่ในแถบเดียวที่อ่านกวาดได้
  ไม่ใช่การ์ดลอยที่ซ้อนอยู่ในการ์ดอีกใบ
- **UI ที่สวยแต่อ่านไม่ออก** — พาสเทลอ่อนบนพาสเทลอ่อน, ตัวอักษรเทาจางบนพื้นสีอ่อน
  เวอร์ชันก่อนหน้ามีปัญหานี้จริง (ตัวอักษรขาวบน `#78B8F2` ได้ contrast 2.11:1)
- **ตารางที่พังบนมือถือ** — fixed grid 6-7 คอลัมน์ที่บีบจนอ่านไม่ได้แทนที่จะ stack
- **ปุ่มและช่องกรอกทรงแคปซูลทุกอัน** — pill สงวนไว้สำหรับ chip/badge/tab ที่มันสื่อความหมาย
  ไม่ใช่ช่องกรอกข้อความสูง 52px
- **อิโมจิแทนไอคอน** — 🔍 ในช่องค้นหาไม่ใช่ไอคอน มันเรนเดอร์ต่างกันทุก OS

## Design Principles

1. **งานมาก่อนดีไซน์** — ทุกหน้าคือคนกำลังทำงานอยู่ ไม่ใช่คนกำลังชม
   ถ้าต้องเลือกระหว่างสวยกับเร็ว เลือกเร็ว
2. **อ่านออกก่อนถึงจะสวยได้** — ทุกคู่สีตัวอักษร/พื้นต้องผ่าน WCAG AA ก่อนเข้า codebase
   ถ้าต้องหยีตา = ผิด
3. **โทเคนเดียว คำศัพท์เดียว** — สี ระยะ มุมโค้ง ขนาดตัวอักษร มาจาก token ชุดเดียว
   ปุ่มบันทึกในหน้า A ต้องหน้าตาเหมือนปุ่มบันทึกในหน้า B
4. **มือถือคือการ stack ไม่ใช่การบีบ** — responsive คือเปลี่ยนโครงสร้าง
   (ตาราง → การ์ด, sidebar → sheet) ไม่ใช่ย่อตัวอักษร
5. **สถานะว่างต้องสอนงาน** — "ไม่มีข้อมูล" ไม่ช่วยใคร บอกว่าทำอะไรต่อได้

## Accessibility & Inclusion

- เป้าหมาย **WCAG 2.1 AA**: ตัวอักษรปกติ ≥4.5:1, ตัวอักษรใหญ่/องค์ประกอบ UI ≥3:1
  ค่า contrast ทุกคู่คำนวณจริงก่อน commit ไม่ประมาณด้วยตา
- Touch target ≥44px บนจอสัมผัส (POS ใช้บนแท็บเล็ต)
- `prefers-reduced-motion: reduce` ต้องมีทางเลือกทุก animation
- ไม่สื่อความหมายด้วยสีเดียว — สถานะมีทั้งสีและข้อความกำกับ (ตาบอดสี)
- ทุก interactive element มี focus ring ที่มองเห็นได้, form field มี `<label>` ผูก `htmlFor`
- ข้อความที่เปลี่ยนแบบ async ใช้ `role="status"` / `aria-live`
- ยังไม่ได้ทดสอบกับ screen reader จริง — การยืนยัน AA เต็มรูปแบบต้องทดสอบด้วย
  assistive technology และรีวิวโดยผู้เชี่ยวชาญ
